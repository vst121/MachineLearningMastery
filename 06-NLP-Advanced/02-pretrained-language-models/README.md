# Pretrained Language Models

This module explores pretrained Transformer language models, their architectural differences, their applications to NLP tasks, and the contextual representations they produce. It covers encoder-only, encoder-decoder, and decoder-only architectures, task-specific model heads, contextual embeddings, and basic model performance analysis.

## Learning Objectives

- Understand pretrained language models and their learned parameters.
- Inspect Transformer configurations, architectures, and parameter counts.
- Compare encoder-only, encoder-decoder, and decoder-only models.
- Apply pretrained models to classification, named entity recognition, question answering, and text generation.
- Extract and analyze contextual token representations.
- Compare contextual and static embeddings.
- Measure inference latency and understand its limitations as a performance metric.

## Core Concepts

### 1. Pretrained Language Models

A pretrained language model learns parameters from large text corpora before being applied to downstream tasks. Pretraining provides reusable representations and language capabilities without requiring every task to start from randomly initialized parameters.

Let the model parameters be represented by:

$$
\theta = \{\theta_1, \theta_2, \ldots, \theta_N\}
$$

The model transforms an input sequence into an output representation:

$$
\mathbf{H} = f_{\theta}(\mathbf{X})
$$

where:

- $$\(\mathbf{X}\)$$ represents the encoded input sequence.
- $$\(f\_{\theta}\)$$ is the pretrained model.
- $$\(\mathbf{H}\)$$ contains the resulting hidden representations.

Pretrained parameters can be used directly for inference or adapted to downstream tasks through additional training.

### 2. Transformer Architecture Families

**Encoder-only models** use bidirectional self-attention to build contextual representations. BERT is a common example, especially for classification, token labeling, and text understanding.

**Encoder-decoder models** combine an encoder that processes the input with a decoder that generates output. T5 is a common example for translation, summarization, and text transformation.

**Decoder-only models** use causal self-attention to predict successive tokens. GPT-style models are widely used for autoregressive text generation.

For causal language modeling, the probability of a sequence is factorized as:

$$
P(x_1, x_2, \ldots, x_n) = \prod_{t=1}^{n}
P(x_t \mid x_1, \ldots, x_{t-1})
$$

A causal attention mask prevents a token from attending to future positions. Encoder-only models generally allow bidirectional attention over valid input tokens, while encoder-decoder models use bidirectional encoder attention and causal decoder self-attention.

### 3. Model Parameters and Hidden States

The total parameter count is the sum of the parameters in the model:

$$
N_{\text{parameters}} = \sum_{p \in \theta} \text{numel}(p)
$$

Trainable parameters are those for which gradient-based optimization is enabled.

For a batch of tokenized sequences, the last hidden-state tensor typically has shape:

$$
\mathbf{H} \in \mathbb{R}^{B \times L \times d}
$$

where:

- \(B\) is the batch size.
- \(L\) is the sequence length.
- \(d\) is the model's hidden dimension.

Each token receives a contextual representation that incorporates information from its surrounding sequence, according to the model's attention architecture.

### 4. Task-Specific Model Heads

Pretrained representations can be combined with task-specific output layers.

For sequence classification, a model may transform a sequence representation into class probabilities:

$$
\mathbf{p} = \text{softmax}(W\mathbf{h} + \mathbf{b})
$$

where \(W\) and $$\(\mathbf{b}\)$$ are the classification head's parameters.

Different NLP tasks require different output structures:

- **Text classification:** predicts a label for an entire sequence.
- **Named entity recognition:** predicts labels for tokens or spans.
- **Extractive question answering:** predicts answer boundaries within a supplied context.
- **Text generation:** predicts or selects successive tokens to construct an output sequence.

The model architecture and task head determine the output format and the meaning of its scores.

### 5. Contextual and Static Embeddings

Static embeddings assign a fixed vector to a word or vocabulary item, regardless of its context.

Contextual embeddings are generated by a model based on the surrounding tokens:

$$
\mathbf{h}_i = f_{\theta}(\mathbf{x})_i
$$

Consequently, the same word can receive different representations in different sentences.

For example, the word _bank_ can refer to a financial institution or the side of a river. A contextual model can encode information that helps distinguish these meanings.

Cosine similarity measures the angular similarity between two vectors:

$$
\text{cosine}(\mathbf{u}, \mathbf{v}) = \frac{\mathbf{u}^{\top}\mathbf{v}}
{\|\mathbf{u}\|_2 \|\mathbf{v}\|_2}
$$

The similarity of contextual representations provides a useful diagnostic, but it is not a definitive measure of semantic equivalence.

### 6. Inference Performance

Inference latency measures the time required for a model to produce an output for a given input.

For \(K\) measured forward passes, average latency is:

$$
t_{\text{avg}} = \frac{1}{K}
\sum_{i=1}^{K} t_i
$$

Model performance depends on several factors, including:

- Parameter count and architecture.
- Input sequence length and batch size.
- Hardware, numerical precision, and memory bandwidth.
- Runtime implementation, caching, and system load.

A simple latency measurement is useful for exploration, but reliable benchmarking requires controlled conditions, warm-up runs, repeated measurements, and consistent workloads.

### Experimental Workflow

1. Load a pretrained model and its tokenizer.
2. Inspect architecture configuration, parameters, and hidden-state dimensions.
3. Compare encoder-only, encoder-decoder, and decoder-only models.
4. Apply pretrained models to representative NLP tasks.
5. Extract contextual token representations and calculate cosine similarity.
6. Measure inference latency and interpret results in the context of model size and hardware.

The experiments use Python, PyTorch, and Hugging Face Transformers. Some experiments download multiple pretrained checkpoints and therefore require internet access unless the model files are already cached.
